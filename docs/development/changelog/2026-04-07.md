## 1. Org Billing Tab

Új "Számlázás" tab az org dashboardon (5. tab a meglévő Áttekintés / Kampányok / Csapatok / Tagok mellé).

**Jogosultság:** ORG_ADMIN szerkesztheti, ORG_MANAGER readonly.

**Szekciók:**

| Szekció | Komponens | Leírás |
|---------|-----------|--------|
| Jelenlegi csomag | `OrgCurrentPlanCard` | Státusz badge, seat progress bar, trial countdown, next billing dátum |
| Csomagok | `OrgPlanComparison` | Team/Org/Scale összehasonlító kártyák, monthly/annual toggle, upgrade modal |
| Egyszeri termékek | `OrgProductCards` | Team Snapshot (€99), Deep Dive (€990), Candidate kreditek (1×/5×/10×) |
| Számlák | `OrgInvoiceList` | Org-szintű számla táblázat Billingo PDF + Stripe receipt linkekkel |

**Új API route-ok:**
- `GET /api/org/[id]/invoices` — org-szintű számla lista (purchases + subscription docs + candidate addons)
- `POST /api/billing/upgrade` — in-app plan upgrade Stripe subscription.update-tel + proration

**Entry pointok:**
- Org Hero footer: "Számlázás →" link (ORG_ADMIN)
- Org Settings: előfizetés szekció egyszerűsítve → link a billing tabra
- Settings seat limit upgrade link → billing tab

**i18n:** 70+ új kulcs (HU/EN) az `org.billing.*` namespace alatt.

**Fájlok:**
- `src/components/org/OrgBillingTab.tsx` — fő tab wrapper

## 2. Saját Trita Checkout Form (Stripe Elements)

A Stripe hosted/embedded checkout lecserélve saját, Trita design-ú fizetési formra.

**Előtte:** Stripe `EmbeddedCheckout` komponens (Stripe design, korlátozott testreszabás)
**Utána:** Stripe `PaymentElement` Trita appearance tokenekkel (sage/sand/ink színek)

**Unified API: `POST /api/billing/create-payment`**

Három mód:
1. **One-time purchase** (`tier=self_plus`): PaymentIntent → azonnali fizetés
2. **Subscription** (`plan=org_monthly`): Trial ha első alkalom, PaymentIntent ha már volt trial
3. **Candidate addon** (`candidatePack=candidate_5`): PaymentIntent → credit jóváírás

**Trial logika:**
- Ha az org-nak már volt `trialEndsAt` → nincs újabb trial, azonnali fizetés szükséges
- Első alkalom → 14 napos trial, subscription automatikusan létrejön

**Komponensek:**
- `src/components/billing/TritaCheckoutForm.tsx` — Stripe PaymentElement wrapper Trita stílussal
- `src/app/billing/checkout/EmbeddedCheckoutClient.tsx` — átírva: create-payment API + TritaCheckoutForm
- `src/components/profile/UpgradeButton.tsx` — navigáció checkout page-re (volt: fetch + redirect)
- `src/components/results/ProgressBar.tsx` — navigáció checkout page-re

## 3. Billing Return/Success Fallback Javítások

A return page 100%-ban a Stripe webhook-ra hagyatkozott. Ha a webhook nem érkezett meg (ngrok issue), a subscription/purchase soha nem jött létre.

**Javítások:**
- **Return page:** idempotens subscription sync a Stripe session adatból
- **Return page:** subscription aktiváció PaymentIntent-ből (post-trial flow)
- **Success page:** PaymentIntent-alapú purchase sync (Elements checkout flow mellett)
- **Checkout route:** trial kihagyás ha az org-nak már volt (`hadTrialBefore` check)

## Stripe Subscription API Megjegyzés

A Stripe SDK v20+ (`stripe` npm package v20.4.1) változás: az `invoice.payment_intent` field eltűnt a Subscription API-ból. A `payment_behavior: "default_incomplete"` + `expand: ["latest_invoice.payment_intent"]` kombináció nem ad vissza `client_secret`-et.

**Megoldás:** Subscription fizetéshez PaymentIntent-et használunk közvetlenül (a price összegével), és a subscription-t a sikeres fizetés után hozzuk létre a return page-en.
